Real time open source transcription that runs anywhere

Streaming speech to text, speaker labels and endpointing, from open weight models. No GPU, no API key and no gated downloads. A 1GB VPS is enough with the light recogniser; the default one wants 4GB.

Everything below is measured on the machine serving this page, and every number is reproducible with a command in the repository.

not connected
Press start and speak. Words appear as they are recognised, the speaker label fills in once there is enough voice to identify it, and a line break marks where a sentence ended.
delay p50- p90- words0 speakers0

What this is trying to be

Meta published Muse Voice Transcribe: one model that streams a transcript, labels who is speaking and marks where an utterance ended, all through a single shared vocabulary. This project asks a narrower question. Can the same capability set be assembled from open weight parts, run on a laptop with no GPU, and cost nothing to operate.

Microsoft has since published MAI-Transcribe-2, cheaper again and top of its own benchmark, but batch: it wants the recording to be finished before it starts. That is a different job, and an easier one, because a system that has the whole file can look ahead and change its mind. The shape being chased here is still Muse's.

The parts exist and are permissively licensed. What does not exist is the agreement between them. One model with a shared vocabulary gets that for free, and four separate models do not. Deciding when a word is final, which speaker it belongs to, and whether a pause ended a thought is the whole of the work here, and it is ordinary Python rather than a training run.

OpenAI shows what that costs when nobody does the assembling. GPT-Transcribe turns a file into text for $0.27 an hour. Live audio is a different model at $1.02. Who spoke is a third model, and it does not stream. Word timestamps are a fourth. Every one of them is good, and there is no combination of them that gives you the whole capability set at once, because the agreement between the signals is exactly the part nobody sells you.

Read Muse's figures as a ceiling and not a target: 3.1% word error rate, 17.5% diarization error, and about 0.16s from speech to a final word. What follows is what this measures against them, including where it falls short, the one case where it does not work at all, and what the three hosted alternatives charge by the hour.

What does not work

Published because a benchmark without its failure case is marketing.

Several people on one microphone will not separate reliably.

A real three person conversation, recorded through a laptop, came back as two speakers, with turn boundaries falling mid sentence. The transcript itself was the most accurate measured anywhere in this project.

The cause is measurable rather than mysterious. Two of the three voices sat at 0.54 cross similarity against 0.55 within, so no threshold exists between them. Four window and threshold combinations were tried and all returned two speakers. Every voice arrives through the same room, the same distance and the same microphone, and that shared channel signature swamps the individual one.

The flat line above is per speaker recordings, where that confound is absent. It is what the same code does with clean capture, and it is why the fix is per speaker streams rather than a better threshold.

How it compares

Honestly: it cannot be placed on the published leaderboards, and pretending otherwise would be the easiest thing on this page to get wrong.

The streaming word error index those charts use is a private corpus, and word error rate moves more between corpora than it does between good systems. Running our own audio and calling the result comparable would be a category error.

The diarization figures come from AMI and VoxConverse, which are public. We have not run them. That is the single most valuable measurement still missing here, and it is on the roadmap rather than in a chart.

What this does instead is publish what it measures, with the command that reproduces it and the bias attached. On the axis that actually differentiates it, the comparison is easier: it runs on a laptop, with no API key, no account and no gated weights.

Three systems are worth naming by price rather than by leaderboard. Muse Voice Transcribe is the streaming ceiling this project was built against, and it bills $0.18 an hour. GPT-Transcribe is the one most people have already used, at $0.27, for files up to 25MB. MAI-Transcribe-2 arrived calling itself the fastest, most accurate and cheapest speech recognition model in the world, at $0.10. None of those claims is in dispute on its own benchmark, and the two that publish a word error rate both beat what is measured here. OpenAI publishes none, so that cell is blank rather than favourable. The row the table cannot hold is the shortest one: the first three send your audio somewhere else, and the last one does not. The rest of the detail sits behind that. Muse runs on the Meta Model API, eight concurrent streams per tenant and sessions capped at 60 minutes. GPT-Transcribe splits the capability set across models, so a transcript, who spoke, low latency and word timestamps are four products rather than one. MAI-Transcribe-2 is Microsoft Foundry, in public preview. None of the three ships weights. This runs on a laptop or a 1GB VPS, CPU only, on open weights with pinned checksums, and admission defaults to the core count capped at 16. On languages it is not close: 25 and more, a long ISO list, and 60 with code switching, against English.

The last column is three published figures from three different corpora and one blank, so it is not a ranking, which the paragraph above the table already said and which a fourth row does not change. Everything in the first three rows is what Meta, OpenAI and Microsoft publish about themselves. None of it was measured here, which is the opposite of the standard the rest of this page holds itself to. The arithmetic is theirs too, and it is only a rate times hours: one always on stream is about 730 hours a month, so $131 at Muse's rate, $197 at OpenAI's and $73 at Microsoft's launch rate, and eight streams, which is where Muse's default ceiling sits, is a little over $1,000. The concession that goes with it is that for a finished recording in one of sixty languages, or for accuracy on hard audio, those rows win and it is not close. What this has is the last one: live, local, and not metered.

Run it

pip install 'hearwrite[onnx,turn,server]'
hearwrite serve --open

That downloads the models on first use, starts the service and opens this page. The base install pulls exactly one package with zero dependencies; the models are fetched from their publishers against pinned checksums, and nothing gated is accepted.
